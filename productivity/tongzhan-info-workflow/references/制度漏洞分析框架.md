## 一、制度漏洞四分法

### 1. 职责边界模糊
**定义**：两个或以上部门对同一事项都有职责，但实际运行中谁都管得少、谁都不主责。
**典型表述**：文件写"由XX部门牵头、XX部门配合"，但无具体分工和协调机制。
**发现问题信号**：
- 文件中出现"会同"、"协商"、"配合"等无约束力词汇
- 某项工作涉及多个部门但无牵头单位
- 跨部门事项经常需要"领导协调"才能推动

### 2. 配套细则缺失
**定义**：上层文件有原则性规定，但县级层面没有配套的操作规程，基层不知道怎么执行。
**典型表述**：文件写"应当"、"不得"、"原则上"，但无具体操作标准。
**发现问题信号**：
- 文件有禁止性规定但无罚则
- 文件要求"建立XX机制"但无机制运作的流程设计
- 政策出台后基层反映"不知道怎么做"

### 3. 监督机制不完善
**定义**：制度规定了要求，但无对应的监督主体、监督方式、追责条款，形同虚设。
**典型表述**：文件写了"应当公开"、"应当报告"，但无公开渠道和未公开的处置措施。
**发现问题信号**：
- 制度运行多年但无任何公开的执法/处罚记录
- 监督检查的频率、方式、责任人均不明确
- 出了问题找不到责任主体

### 4. 制度空白
**定义**：某类人群、事项、领域处于"三不管"状态，没有对应的管理制度。
**发现问题信号**：
- 新兴群体/业态出现后长期无统战工作跟进（如：网络主播、外卖骑手、网约车司机）
- 跨领域事项在各部门职责中均未明确提及
- 某类人群想办事找不到受理部门

## 二、发现路径与搜索关键词模板

### 路径1：Wiki政策文件库
```
~/wiki/entities/policy-*.md
→ 读每个文件的"执行层面问题标注 ⚠️"章节
```

### 路径2：Bing搜索（browser_navigate）
```
https://cn.bing.com/search?q=关键词+site:gov.cn
```

**搜索模板**：

| 场景 | 搜索关键词模板 |
|------|--------------|
| 查某制度执行问题 | "《XX条例》执行问题" |
| 查职责边界争议 | "XX工作+部门职责+推诿" |
| 查细则缺失反映 | "XX规定+无法执行+不知道怎么搞" |
| 查监督缺失 | "XX监管空白+无人管" |
| 查新兴领域空白 | "网络XX+统战工作+覆盖" |
| 查基层反映 | "基层反映+XX制度+不合理" |

### 路径3：本地文件（zipfile读取）
```python
import zipfile, re
def read_docx_text(fpath):
    with zipfile.ZipFile(fpath, 'r') as z:
        with z.open('word/document.xml') as f:
            content = f.read().decode('utf-8')
            text = re.sub(r'<[^>]+>', ' ', content)
            text = re.sub(r'\s+', ' ', text).strip()
    return text

# 自查汇报路径

```

## 三、问题类信息稿 vs 制度漏洞信息稿的区别

| 维度 | 问题类（热点事件） | 制度漏洞类 |
|------|-----------------|-----------|
| 核心 | "发生了什么坏事" | "制度哪里有毛病" |
| 切入点 | 事件/人物/时间 | 文件/条款/机制 |
| 回答的问题 | 现象是什么、谁受害、为什么 | 哪个环节卡住了、为什么卡住、如何改 |
| 数据来源 | 事件本身的数据 | 制度运行中的普遍性表现 |
| 写作难度 | 较易（事件清晰） | 较难（需要制度分析能力） |
| 稳定性 | 低（热点过了就无效） | 高（制度漏洞长期存在） |

## 四、选题推荐原则

1. **优先选配套细则缺失**：有文件依据但基层不知道怎么执行，角度清晰
2. **慎选制度空白**：空白类需要大量调查才能写充实，易空洞
3. **监督类要谨慎**：无数据支撑时容易写成"呼吁型"文章
4. **职责边界类优先选多部门交集点**：台胞同等待遇涉及部门最多，最容易出选题
