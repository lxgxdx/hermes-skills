# 三维度评估法（🟢/🟡/🔴 标记法）

> 本文件是"二B、制度漏洞类选题流程"和"二、临时选题建议流程"配套的**标准化评估方法**。当用户问"看看还有什么能写的"或"推荐几个选题"时，**用此法批量评估候选选题并按优先级排序**——比单条推荐更高效。

---

## 一、为什么需要三维度评估

**问题**：用户问"还有没有别的能写的"，直接列 20 个选题不是答案——用户需要的是**优先级排序的 TOP 5**。

**三维度评估的目标**：
1. **批量评估**：一次扫多个候选，快速识别🟢/🟡/🔴档位
2. **避免空洞推荐**：四有标准兜底，缺数据/案例的直接降档
3. **县区可写性优先**：领导最爱看"县区能写"的稿子
4. **效率优化**：写作难度★★以下的优先排产

---

## 二、三维度评分标准

### 维度 1：四有标准（最高权重）

| 档次 | 含义 |
|------|------|
| ★★★★ | 案例+数据+来源+角度全齐（信息稿骨架完整） |
| ★★★ | 缺一项（如有数据无案例） |
| ★★ | 缺两项（如只有方向性描述） |
| ★ | 缺三项及以上（仅是话题） |

**用户原话**："你这个题目还有前面的，你没提出存在什么问题之类的呀，你现在只是描述了一个事实"——四有标准是问题类信息稿的底线。

### 维度 2：五莲贴合度

| 档次 | 含义 |
|------|------|
| ★★★★★ | 县区可直接调研（5 莲县本地有完整场景） |
| ★★★★ | 县区有部分场景，可问本地数据 |
| ★★★ | 县区偶有发生，参考外地为主 |
| ★★ | 县区罕见，偏省级/全国视角 |

### 维度 3：写作难度

| 档次 | 含义 |
|------|------|
| ★★ 易 | 素材易得，30 分钟可出初稿 |
| ★★★ 中 | 需要查 1-2 个文件 + 调研 |
| ★★★★ 难 | 需要大量补充 + 多方访谈 |

---

## 三、🟢/🟡/🔴 档位判定

### 🟢 优先
- **条件**：四有 ★★★+ 且 五莲 ★★★★+ 且 难度 ≤★★
- **操作**：直接写入 TOP 5 候选 + 询问用户选择

### 🟡 一般
- **条件**：缺一档（如四有★但五莲★★★★★）或两档轻微缺
- **操作**：作为备选，如果 🟢 用完可推

### 🔴 不推荐
- **条件**：缺三档及以上（如缺真实案例 + 县区无场景 + 写作难度大）
- **操作**：从候选中剔除，避免推荐

   - ★★★★★ > ★★★★ > ★★★

## 五、批量化执行代码

```python
# 32 漏洞 + 三维度评估的批量化
vulns = [
    # (标签, 政策, 四有, 5莲, 难度, 推荐度, 推荐理由)
    ("工商联-商会家族化", "gongshanglian", 3, 5, 2, "🟢 优先", "..."),
    # ... 32 个
]

# 排序：🟢 > 🟡 > 🔴，同档内按领导权重
order = {"🟢 优先": 0, "🟡 一般": 1, "🔴 不推荐": 2}
vulns_sorted = sorted(vulns, key=lambda x: order[x[5]])

# 统计
priority = [v for v in vulns if v[5] == "🟢 优先"]
general = [v for v in vulns if v[5] == "🟡 一般"]
not_rec = [v for v in vulns if v[5] == "🔴 不推荐"]
print(f"🟢 {len(priority)} | 🟡 {len(general)} | 🔴 {len(not_rec)}")
```
