## 二、本次新发现：3个值得编码的坑/教训

### 坑 1：排重参考文件 `references/选题排重规则.md` 实际不存在

**现象**：
- 任务 prompt 要求"读 `references/选题排重规则.md` 确认长线禁止关键词 + 近3天选题记录"
- 实际执行 `read_file` 该路径时返回 `File not found`（错误 0 字节）
- 该文件**从未在 5 月任何一次 cron 中被生成或维护过**

**正确处理**（本次执行的做法）：
- 跳过排重参考文件读取
- 直接读近 3 天的 `问题类选题_YYYYMMDD.md` 文件（5/30、5/31、6/1）
- 同时读 `references/daily-topics-log.md` 和 `references/2026-05-31-topics-log.md` 合并实时排重记录
- 排重检查只看近 3 天真实选题 + Wiki 政策库标注

**对 SKILL.md 的影响**：
- 步骤 1 的"读 references/选题排重规则.md"应标注为"⚠️ 该文件可能不存在，失败时降级为读近 3 天真实选题文件"
- 这是 cron prompt 与实际目录状态的脱节，未来生成 cron 任务描述时应核对路径存在性

### 坑 2：Bing `browser_navigate` 在 cron 环境对中文 site 限定词完全失效

**现象**：
- `browser_navigate("https://cn.bing.com/search?q=台胞 社保 充值 有问题 2026 site:gov.cn")`
- 返回 189 万条结果，但首屏全是 "哔哩哔哩" 站外内容（和搜索词毫无关系）
- 点击 site:gov.cn 的搜索结果链接也跳到无关页面
- 标题里的 "BILI" 被 Bing 误识别为查询实体

**正确处理**（本次执行的做法）：
- 跳过 Bing 搜索
- 直接用 curl + grep 提取观察者网台湾版的当日新闻列表
- 通过 `https://www.guancha.cn/politics/YYYY_MM_DD_NNNNNX.shtml` URL 模式直接抓文章全文

**对 SKILL.md 7.0 节的更新**：
- 既有 7.0b/7.0c 写"`browser_navigate` + Bing HTTPS 最高优先"——本次实测**证伪**了这一条
- 正确优先级应为：`browser_navigate` + 权威新闻网站（guancha.cn/sara.gov.cn）>> Bing
- Bing 在 cron 凌晨对中文 site 限定/复杂查询的可用性比预期差

## 三、本次新发现：制度漏洞的第 5 类

> 详见 `references/制度漏洞分析框架.md` 后续更新（**新分类，建议补充到该文件**）

**第 5 类：跨主体信息不共享导致违规成本"归零"**

**核心识别信号**（2026-06-02 cron 实战首次系统化）：
- 制度本身存在（既不是空白，也不缺细则）
- 多个平等主体之间的资格/资质/处罚信息不互通
- 同一对象被一方除名/处罚后，可在另一方"洗白"重新获得资格
- 违规成本实质上归零

**典型发现位置**：
- Wiki 政策库：`policy-religious-personnel.md` 第 3.3 节"宗教团体'自我管理'监督弱"中"宗教团体之间信息不共享"标注
- 本次 cron 选题 3 即基于此漏洞生成：《教职人员"被除名换团体重新注册"漏洞》

**与既有 4 类的关键区别**：
- 不属于"制度空白"——制度有资格认定、备案、处分规定
- 不属于"监督机制不完善"——处分机制运行正常
- 不属于"配套细则缺失"——细则齐全
- 核心问题在**信息共享的横向打通**——制度纵向是完善的，横向是断裂的

## 五、对 7.2a 节（"高热度≠新文章"陷阱）的补充

既有 7.2a 节提到观点列表高阅读量文章可能是"前几天置顶"。本次 cron（6/2）观察到：
- 头版首条"反制日菲！中国海警实现环台岛执法"阅读量 **135**（非常低）
- 6/1 头版首条"又来，'中国要2027武统'"在 6/2 已爬升至阅读量 82438（说明确实是当天新增）

**结论**：阅读量 4 位数（如 135）几乎可以确定是**当天 0-2 小时内发布**的突发新闻；阅读量 5 位数以上（>10000）通常是 1-2 天前发布的。这是 7.2a 节"低阅读量=当天新增"判断的更精确量化标准。
