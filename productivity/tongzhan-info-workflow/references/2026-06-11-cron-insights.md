## 七、6/11 cron 关键方法论总结

### 7.1 Wiki 政策库"动态重扫+剩余富矿预测" = 可预测作业模式

- 每次 cron run 第一步：`ls -lt ~/wiki/entities/policy-*.md` 列出全部
- 用 Python 脚本提取所有"**xx漏洞** — xx"标注
- **6/11 新增**：输出剩余富矿明细+消耗速率+预计可写篇数
- **6/11 新增**：异常检测（文件大小增长>50%但扫描漏洞=0 → 触发人工深度阅读）

### 7.2 "双低=当天新增" = 台湾方向新闻判断法（6/01 提出，6/11 验证）

- 阅读量+评论数双低（如170/838/0/0）= 真实当天新增
- 阅读量高+评论数高 = 前日热点延续置顶
- 观点列表 = 多日置顶观点文章
- 新闻已从置顶消失 = 已过时

### 7.3 制度漏洞"四层切入法"+"双面叙述法" = 五维框架（6/11 升级）

**四层切入法**（立法层/元问题层/执行层/微观切口层）扩展为**五维框架**：
- **立法层**：法律条款本身的滞后
- **元问题层**：制度设计本身的结构性问题
- **立法技术层**：具体技术指标的缺失（量化指标、判定标准、性质明确）— **6/11新增**
- **执行层**：基层执行中的梗阻
- **微观切口层**：从具体数字/事件切入

**双面叙述法**（立法层 vs 执行层）扩展为**双轴叙述**：
- 立法层 vs 执行层（6/08）
- **内部治理 vs 外部治理**（6/11新增）

### 7.4 维度互补排重 = 四维/五维互补矩阵（6/11 实证）

3个制度漏洞选题覆盖3个不同维度（立法技术层×2 + 内部治理层×1），与6/03"执行层"、6/04"内部程序"、6/08"元问题层+外部治理"形成完整维度矩阵。**每个新选题必须落在不同维度上**，避免与已写选题在同一维度重复。
