# 公众号内容制作：HTML 截图方案

> 适用场景：需要精确控制设计风格时（如统战主题配图），AI 图像生成随机性太大，用 HTML + 截图替代。
>
> ⚠️ **重要教训（2026-05-09）**：自行设计的 HTML 风格用户不满意（说"不行"），原因是凭空设计的配色和布局与真实公众号风格不符。**GitHub 搜索 0 结果后，正确做法是找到做得好的公众号文章，用浏览器"查看网页源代码"提取实际 HTML/CSS 结构，然后基于真实样本编写模板。**

## 核心结论

**AI 图像生成（如 MiniMax image-01）对政治概念理解有限，随机性高，不适合需要精准政治表达的配图。推荐方案：**

```
HTML/CSS 渲染 → Chrome headless 截图 → 直接用作公众号配图
```

**优势：**
- 配色、布局、字体大小 100% 代码控制，无随机性
- 截图效果 = 成片效果所见即所得
- 文字精准，不存在 OCR 或 AI 绘图文字错误
- 可直接复制 HTML 文字进公众号编辑器

## 标准工作流

### 第一步：找到真实样本并提取样式

1. 用 browser_navigate 打开做得好的统战类公众号文章
2. 右键"查看网页源代码"，提取其中的 HTML/CSS 结构
3. 基于真实样本的配色、字体、间距编写 HTML 模板

### 第二步：编写 HTML 文章

- 文件保存到 `/tmp/<topic>_article.html`
- 基于真实样本的样式调整，而非自行设计配色

### 第三步：启动本地 HTTP 服务器

```bash
terminal(background=true, command="cd /tmp && python3 -m http.server 8765")
```

### 第四步：Chrome headless 截图

```bash
google-chrome --headless --disable-gpu \
  --screenshot=/tmp/output.png \
  --window-size=750,1400 \
  --force-device-scale-factor=2 \
  "http://localhost:8765/<topic>_article.html"
```

**参数说明：**
- `--window-size=750,1400`：移动端阅读尺寸（适合公众号竖版）
- `--force-device-scale-factor=2`：2x 分辨率（高清）
- 截图保存为 `/tmp/output.png`

### 第五步：发送飞书预览

```
send_message(target="feishu:oc_7c656031826c26b15f17d010097f3619",
             message="...文字内容...\n\nMEDIA:/tmp/output.png")
```

## MiniMax 图像生成 API（备选方案）

> 仅当需要生成示意性配图（非政治内容）时使用，如文章封面图、科技概念图。

**正确端点（实测有效）：**
```
POST https://api.minimaxi.com/v1/image_generation   ✅
POST https://api.minimax.io/v1/image_generation     ❌ (无效)
```

**调用方式：**
```bash
MINIMAX_KEY=$(grep MINIMAX_CN_API_KEY ~/.hermes/.env | cut -d= -f2)
curl -s -X POST "https://api.minimaxi.com/v1/image_generation" \
  -H "Authorization: Bearer $MINIMAX_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "image-01",
    "prompt": "英文 prompt 描述",
    "aspect_ratio": "16:9"
  }'
```

**响应中的图片 URL 有时效性（约 30 分钟），下载后尽快使用。**

## 关键文件路径

| 用途 | 路径 |
|------|------|
| 临时 HTML 文章 | `/tmp/<topic>_article.html` |
| 截图输出 | `/tmp/<topic>_full.png` |
| 本地 HTTP 服务器端口 | `8765` |

## 排错

- **Chrome 找不到**：检查 `/usr/bin/google-chrome` 是否存在
- **截图空白**：确认 HTTP 服务器已启动，`curl http://localhost:8765/<file>` 有返回
- **飞书图片发送失败**：使用 `MEDIA:/tmp/output.png` 格式，路径必须是绝对路径
