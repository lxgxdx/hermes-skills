# 统战部文件批量规范化重命名

按统一规范批量给文件夹里的文件改名前的工作流。**核心理念：先核对、后改名；先出表、后执行；原件永远不动。**

## ⚡ QuickRef

**核心规范模板（2026-06 确立）：**
- 党委：`中共XXXX党委落实统战工作责任制情况自查报告.扩展名`
- 党组：`中共XXXX党组落实统战工作责任制情况自查报告.扩展名`
- 党工委：`中共XXXX党工委落实统战工作责任制情况报告.扩展名`
- 党支部：`中共XXXX党支部落实统战工作责任制情况报告.扩展名`

**两件不动的事：**
1. 任何"原件/"、"原文件名备份/"、"backup/"、"0_原始/" 等备份子目录**永远不动**
2. 已经改过名的、命名已合规的文件**不再二次重命名**

**批量改名铁律：**
- 先出"原名 → 新名"映射表 → **让用户审核** → 再执行
- 执行前先做 1-2 个文件**试改**验证脚本无误
- 执行后 `ls` 验证改名成功 + 抽样 `cat`/`pdftotext` 验证文件没坏

---

## 工作流（5 步）

### 步骤 1：扫描目录 + 识别"原件"边界

**输入：** 目标文件夹绝对路径
**输出：** 文件清单（文件名 + 大小 + 修改时间 + 扩展名）

**关键检查：**
- [ ] 是否有 `原件/`、`原版/`、`backup/`、`0_原始/` 等备份子目录？→ **保留原样不动**
- [ ] 文件格式分布：`.doc`、`.docx`、`.pdf`、`.wps` 都可能出现
- [ ] 是否有重复文件？（同名不同扩展名 / 大小近似但名称不同）

```bash
TARGET="/path/to/folder"
ls -la "$TARGET"
ls -la "$TARGET"/原件/ 2>/dev/null   # 备份目录（如果有）
find "$TARGET" -maxdepth 2 -type f | wc -l   # 文件总数
```

---

### 步骤 2：识别"信息不全"文件

把文件分成 3 类：

| 类别 | 特征 | 处理方式 |
|------|------|---------|
| **A 类：信息完整** | 文件名含单位名 + 含"党委/党组" | 可直接改 |
| **B 类：单位不全** | 文件名有"党委/党组"但缺单位全称（如"党组小红头…"）| **必须读内容** |
| **C 类：性质不全** | 文件名有单位但缺"党委/党组"（如"潮河镇统战…"）| **必须读内容** |
| **D 类：完全模糊** | 文件名只有"自查报告(2)"、"(1)(1)" 这种 | **必须读内容** |

**信息提取优先级（从高到低）：**
1. 文件正文第一行 / 标题（最权威）
2. 落款处单位名
3. 文件名中的单位名
4. 文件名格式"单位名+党委/党组"推断
5. 都拿不到 → 问用户

---

### 步骤 3：抽取内容判定单位性质

**根据文件类型选方法：**

| 扩展名 | 抽取方式 | 命令 |
|-------|---------|------|
| `.docx` | libreoffice 转 txt | `libreoffice --headless --convert-to txt --outdir /tmp/x file.docx` |
| `.doc` | libreoffice 转 txt（兼容性好）| 同上 |
| `.wps` | libreoffice 转 txt | 同上 |
| `.pdf` | **🆕 M3 优先**：直接 `vision_analyze` 读首页 | `pdftotext` 兜底 |
| 图片（截图/扫描件）| **🆕 M3 优先**：`vision_analyze` | M2.7 才走 OCR |

**🆕 M3 模型下 PDF/图片读取新范式（2026-06 确立）：**

当前对话模型是 `minimax-cn/MiniMax-M3`，**有原生多模态视觉**。处理 PDF/图片时**不要**走老路的 `pdfimages` + EasyOCR，直接用 `vision_analyze` 一行搞定：

```python
# 文字型 PDF — 先用 pdftotext 试，没有再 vision_analyze
import subprocess
text = subprocess.run(['pdftotext', '-l', '2', pdf_path, '-'],
                     capture_output=True, text=True).stdout
if not text.strip():
    # 兜底：转图片用 vision_analyze
    subprocess.run(['pdftotext', pdf_path, '-'])  # 全文
    # 或直接：vision_analyze(image_url=pdf_path, question="...")
    pass

# 图片型 PDF / 扫描件 — 直接 vision_analyze
from hermes_tools import vision_analyze
# 方法 1：先 pdftoppm 转首页图片
subprocess.run(['pdftoppm', '-f', '1', '-l', '1', '-png', '-r', '200',
                pdf_path, '/tmp/page1'])
vision_analyze(image_url='/tmp/page1-1.png',
              question="这是哪个单位关于什么的文件？标题第一行是什么？落款是什么？")

# 方法 2：vision_analyze 支持 PDF 路径（多数情况下可直接读）
# vision_analyze(image_url=pdf_path, question="...")
```

**何时回退到 OCR 流水线：**
- M2.7 对话（无视觉）→ 必须走 EasyOCR
- vision_analyze 失败/超时 → 回退 OCR
- 需要结构化坐标（bbox）数据 → EasyOCR 返回 JSON 带 bbox

**OCR 接口（仅 M2.7 / 兜底用）：**
```bash
# 1. 提取首页图片
pdfimages -f 1 -l 1 -png "file.pdf" /tmp/ocr_p1
# 2. POST 到内网 OCR
curl -s -X POST http://192.168.88.68:8082/ocr \
  -F "image=@/tmp/ocr_p1-001.png" \
  | python3 -c "import sys,json; [print(r['text']) for r in json.load(sys.stdin).get('results',[])]"
```

**判定党委/党组的规则：**

| 单位类型 | 文件正文特征 | 命名用词 |
|---------|------------|---------|
| 党的基层委员会（镇/街道/机关/国企/事业单位党的委员会）| "X镇党委"、"X委" | 党委 |
| 政府组成部门/局/办的领导班子党组 | "X局党组"、"X机关党组" | 党组 |
| 党的工作委员会（县直机关工委、教育工委等）| "X工委" | 党工委（**注意：用户给的格式只到"党委/党组"，党工委需询问**）|
| 总支/支部 | "X党支部" | 党支部 |

**常见五莲县级单位归类参考：**

| 单位 | 性质 | 命名 |
|------|------|------|
| 各乡镇（街道）| 党委 | X镇党委 |
| 县直各局（如发改局、财政局、司法局）| 党组 | X局党组 |
| 县直机关工委 | 党工委 | 县直机关工委 |
| 教体系统 | 教育工委 | 县委教育工委（视为党委级）|
| 国有企业（农发集团、城发集团）| 党委 | X集团党委 |
| 税务局 | 党委 | X税务局党委 |
| 五莲山省级旅游度假区 | 党工委 | 度假区党工委 |

### 步骤 4：生成映射表 + 边界 case 清单

**输出格式（用户面前展示）：**

| # | 原文件名 | 新文件名 | 性质 | 备注 |
|---|---------|---------|------|------|

**必须问用户的边界 case：**
- 不在"党委/党组"模板里的（如党工委、党支部、总支）
- 单位名是否加"中共"前缀（"中共五莲县X局党组" vs "五莲县X局党组"）
- 是否加"县委/县直"等上级归属词
- 同名但不同格式的（如"局党组"vs"机关党组"）
- 文件原名已合规的是否要二次重命名

**对"原件/"子目录的处理：**
- **永远不动原件/子目录**
- 也不要给原件里的文件加"序号"前缀
- 如果原件/是用户的工作底稿，主目录是整理后的版本

---

### 步骤 5：用户审核后批量执行

**用户明确"按你说的来"或"开始改"后才能执行。** 不允许自动执行。

**执行前 1-2 个试改：**
```bash
cd "$TARGET"
# 干跑（不实际改名）
mv -n "原文件名" "新文件名"   # 看看效果
```

**正式执行：**
```bash
cd "$TARGET"
# 用 while read 循环处理（避免空格/特殊字符问题）
while IFS= read -r old; do
  new="${mapping[$old]}"
  [ -f "$old" ] && mv "$old" "$new" && echo "✓ $old → $new"
done <<< "$(printf '%s\n' "${!mapping[@]}" | sort)"
```

**执行后验证：**
```bash
# 1. 确认所有新文件存在
for new in "${new_names[@]}"; do
  [ -f "$TARGET/$new" ] || echo "❌ 缺失: $new"
done
# 2. 确认旧文件全部消失
for old in "${old_names[@]}"; do
  [ -f "$TARGET/$old" ] && echo "⚠️ 旧名还在: $old"
done
# 3. 抽查一个文件验证内容完好
pdftotext "$TARGET/某.pdf" - 2>/dev/null | head -5
```

## 决策树（速查）

```
用户说"重命名文件夹下文件" →
  ├─ 有"原件/"子目录？
  │   └─ 是 → 原件/不动，只改主目录
  ├─ 命名规范明确？
  │   ├─ 明确（用户给了完整模板）→ 走步骤 1-5
  │   └─ 模糊 → 先问用户确认模板再开工
  ├─ 文件数 < 20？
  │   ├─ 是 → 一次性扫完 + 读内容 + 出映射表
  │   └─ 否 → 抽样读内容（先 5-10 个），剩余推断 + 问用户
  └─ 文件扩展名分布？
      └─ 出现 .doc/.wps → 优先用 libreoffice 转 txt
```

## 异常处理索引

| 情况 | 解决方法 |
|------|---------|
| `.doc` 用 cat/strings 读出来是乱码 | `libreoffice --headless --convert-to txt` 转 |
| `.pdf` 用 `pdftotext` 出来是空白 | `pdfimages` 抽图 → 走 OCR |
| OCR 置信度 < 0.5 | 人工核对或读其他页 |
| OCR API 字段不对（报 `image` missing）| 改用 `-F "image=@file"`（不是 `file=@file`）|
| OCR API 报 `Field required: image` | 字段名是 `image` 不是 `file`，POST 时用 `-F "image=@..."` |
| 文件名含空格/中文/特殊字符 | `mv` 用引号包起来，**不要**用 `for f in $(ls)` |
| 重复文件名（改名后存在）| 加 `2>/dev/null` 或加序号后缀 |
| 用户给"按你判断"或"开始"指令 | 才执行，否则**只出映射表等审核** |
| 同名但不同单位的文件 | 在新名中显式加单位标识 |
| 内容标题 vs 文件名冲突（如"教体系统"实际是"教工委"）| **以内容标题为准**（文件里的红头/落款最权威）|

## Pitfalls（踩过的坑）

1. **不要直接用 `cat` 读 `.doc`** — 输出是二进制乱码
2. **不要用 `python-docx` 读 `.doc`** — 它只能读 `.docx`
3. **不要假设 `pdftotext` 一定能出文字** — 图片型 PDF 出来是空白，必须走 OCR
4. **不要跳过"出映射表"直接批量改** — 40 个文件一旦改错，回退成本极高
5. **不要碰"原件/"目录** — 那是工作底稿，动了就回不去
6. **不要根据文件夹名判定党委/党组** — 文件正文里的"X镇党委"才是权威
7. **不要给图片型 PDF 用 `strings` 提取** — `strings` 只能读 PDF 的 ASCII metadata，读不出图像内容
8. **不要忘记改完后用 `ls` 验证** — `mv` 静默失败时（比如同名目标已存在）不会有任何提示
