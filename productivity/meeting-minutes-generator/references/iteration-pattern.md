# 部务会会议记录迭代修订模式（2026-06-02 沉淀）

## 典型工作流（用户视角）

1. 用户首次提供材料 → 整理 v1 → 多轮迭代 v2/v3/v4/v5
2. 用户定稿 v5 → 之后进入**修订模式**（用户口头/文字指出某处不对）
3. 修订模式流程：
   - **明确指出"用的是哪个文件"**（用户原话："我现在用的是会议记录_2026年第5次部务会.docx 这个文件"）
   - 用户具体描述问题
   - AI 直接 patch v5 脚本，重新生成（覆盖目标 docx）
   - 不必每次都重新问"你用哪个文件"

## v5 → 用户修订案例（累计三轮，2026-06-02）

### 第一轮：议题一"会议指出..."把原文材料概括了
- **错误**：v5 把议题一参考资料（特朗普会谈/防灾减灾）的大段原文改写成"会议指出...合作为主的积极稳定..."、"会议指出...统筹高质量发展和高水平安全..."
- **正确**：
  - 领学句只写事实："X 同志领学了 Y"
  - 之后接"会议要求，一要...二要..."（部务会自己的贯彻落实意见，**不是原文复述**）
  - 录音里没具体研究意见时，AI 自行写 1-2 句符合公文规范的贯彻落实要求
  - 领学句必须穷举议题标题里所有领学对象（议题一标题 3 项，领学句漏了"普京"）

### 第二轮：议题二同问题 + 议题一改成"会议要求"后内容仍是凭空套话
- 用户原话："这种学习类的贯彻落实意见，还是得根据学习的内容来说，不能凭空生成，像你刚刚写的二要树牢底线思维、极限思维，扎实做好宗教领域安全、意识形态安全等各项工作，切实维护全县统一战线领域和谐稳定。就跟第一议题学习的内容没什么关系"
- **修正**：每一条"会议要求"都必须从本次学习内容本身推导（议题一从"外交+防灾减灾"推导；议题二从"正确政绩观"推导）

### 第三轮：议题六张部长讲话 + 标点符号
- 用户原话：「为民务实」，不要用「」这种符号，可以用双引号，这种符号在手写的部务会会议记录当中一般是不存在的
- 用户原话：第六个议题，张部长讲话，也要尽量采用原来的录音文字进行整理，没有的话，再根据本次部务会的内容适当发挥
- **修正**：
  1. 议题六讲话先搜 REC00XX 中"张道伟/张部长"讲话时段，提取核心要点；没有的部分根据议题一到五的统揽适当发挥
  2. 中文标点只用"双引号"，不用「」/『』/【】等
  3. 议题六讲话**不可使用"深入学习/突出重点/强化自身建设/抓好工作落实/守好安全底线"通用党政模板**

## 关键教训汇总（v5 → v6 修订链）

1. **"会议指出/要求" ≠ 原文复述** —— 必须是部务会研究形成的贯彻落实意见
2. **贯彻落实意见 ≠ 通用党政套话** —— 每一条都要从本次学习/讨论内容推导，录音/议题内容里能找到依据
3. **讲话类议题 ≠ 通用模板** —— 必须用录音原文整理，无录音时按本次会议内容发挥
4. **公文标点 ≠ 「」** —— 党政公文/手写记录里只使用中文双引号 "..."
5. **领学句必须穷举**议题标题中的所有领学对象
6. **Python 字符串内嵌中文双引号** 需要 `\"...\"` 转义，否则 SyntaxError

## 修订操作的关键命令

```bash
# 1. 读 v5 脚本定位要改的行
grep -n "议题一\|特朗普\|会议指出" /home/lxgxdx/build_meeting_record_v5.py

# 2. patch 替换错误段落
patch 工具直接改 build_meeting_record_v5.py

# 3. 重新生成（覆盖目标 docx）
python3 /home/lxgxdx/build_meeting_record_v5.py

# 4. 转 txt 验证修改
cd /tmp && libreoffice --headless --convert-to txt \
  "/mnt/nfs/2026年统战工作/1.办公室/9.部务会/5.27/会议记录_2026年第5次部务会.docx" \
  --outdir /tmp/
sed -n '12,18p' /tmp/会议记录_2026年第5次部务会.txt
```

## v5 脚本的位置与命名

- 脚本路径：`/home/lxgxdx/build_meeting_record_v5.py`
- 历史版本：`build_meeting_record_v2.py` / `v3.py` / `v4.py`（已弃用，保留作回滚备份）
- 输出路径：`/mnt/nfs/2026年统战工作/1.办公室/9.部务会/<日期>/会议记录_YYYY年第N次部务会.docx`

## ⚠️ 易踩坑

- 每次"小改"都重新生成整个 docx 会丢失 LibreOffice 缓存 → 必须先删 `/tmp/会议记录_2026年第5次部务会.txt` 再转
- 用户**没明说时不要自动改议题二** —— 议题二也可能有同样问题，但等用户单独指出再改
- 修订后**等用户审阅**，不要立刻飞书发 PDF 通知
