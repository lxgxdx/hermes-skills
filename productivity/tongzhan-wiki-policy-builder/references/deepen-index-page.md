# 索引页深化操作手册 — 与全文页深化的关键区别

> 适用场景：被深化的政策页是**索引页**（`head -15` 显示"本页面为索引页"或"实际法律条文和法律责任分析见 government-law-wiki"），而不是 P15 章程类的全文页。
>
> 沉淀日期：2026-06-09（基于 policy-religion-regulations.md 深化实践）

## 1. 为什么索引页需要单独的深化手册

| 维度 | 全文页（如 P15 章程） | 索引页（如 P01 宗教条例） |
|------|----------------------|--------------------------|
| 内容分工 | 本知识库存全文 + 执行层面分析 | 政府法律知识库存全文，**本知识库只做执行层面分析** |
| "内容稀薄"原因 | 真的没内容 | 内容在兄弟知识库（government-law-wiki），本知识库只做分析 |
| 深化方向 | 补全文 + 补分析 | **补案例 + 补横向分析框架**（不补全文，违反分工） |
| 衡量"深化完成" | 全文覆盖率、5 类问题标注密度 | **真实执行案例数 + 案例间逻辑串联完整度** |
| 常见错误 | "概念解释"堆砌但不补案例 | 误以为"内容少=全文少"，去补法律条文——破坏知识库分工 |

**判断索引页 vs 全文页的方法**（1 行命令）：
```bash
head -15 ~/wiki/entities/policy-{slug}.md | grep -l "本页面为索引页\|实际法律条文" 
# 返回 0 = 全文页；返回 1 = 索引页
```

## 2. 索引页深化的 4 个标准动作

### 动作 1：补真实执行案例（最优先）

索引页最容易出现"⚠️待补充真实案例"或"暂无经核实的真实案例"——因为之前建设时"重点"是法律解读而不是案例。

- **目标**：至少 2-3 条**近 3 个月内**权威来源（gov.cn / 全国性社团官网 / 新华社）的真实案例
- **来源优先级**（与 SKILL.md 步骤 3 一致，但**特别推荐**）：
  - 中国佛教协会官网 `chinabuddhism.com.cn`（2026-06-09 验证：内容质量极高，详见 SKILL.md 源表第 14 项）
  - 中央统战部通稿
  - 国家宗教事务局、国家民委署名文章
- **不补**：模型领域知识推测的"假设性示例"（这是污染知识库的行为）

### 动作 2：补案例间逻辑串联（横向分析）

P15 全文页深化的产出是"5 类问题标注 + 6 条案例"——案例**独立**列出即可。索引页深化应**更进一步**：用**案例间逻辑串联**展示多案例如何**共同暴露同一制度漏洞**。

**推荐格式**（ASCII tree）：

```
《XXX条例》"硬法"层面
        │
        ├─ 问题1  ── 案例A回应 ── 但具体细则缺失
        ├─ 问题2  ── 案例B回应 + 实际执行（CASE-C）─ 退出标准"原因清单"未公开
        ├─ 问题3  ── 完全无对应 ── 监管真空
        └─ 问题4  ── 案例D承认短板 ── 但无配套方案
                │
                └─ 软法-硬法中间地带 = 基层执法真实困境
```

**核心制度问题总结**（在 ASCII tree 之后，3-5 条）：
1. 问题的横向共性
2. 涉及多部门/多层级
3. 基层可感知的影响
4. 信息稿可切入角度

### 动作 3：补"软法-硬法"等横向分析框架（区别于 5 类问题）

5 类问题标注是**线性列举**（每类独立）。索引页深化的**新方法论**：

- **第 6 框架：软法-硬法衔接**——适用于**所有有"全国性社团章程/规划"的政策领域**（宗教/工商联/光彩/侨联等）
  - 软法（社团自律章程/规划/守则）：无强制力，违反只能"批评教育"
  - 硬法（《XXX条例》）：有强制力，可行政处罚
  - **中间地带**：行为违反软法但未触及硬法具体条款——基层陷入"够不上处罚、够不上追责"
  - 识别该模式：政策页所列法规**同时存在国家法规和全国性社团自律文件**时
- **第 7 框架：上位法-下位法衔接**（类似但不同）
  - 上位法（《XXX条例》国务院令）— 原则性
  - 下位法（实施细则/地方实施条例）— 操作性
  - **衔接真空**：上位法说"应当 X"，下位法实施细则迟滞或未出台

**索引页应至少补 1 个横向框架**——这是与全文页深化的**结构性差异**。

### 动作 4：更新 frontmatter + 关联页面 + 五莲县级启示

- frontmatter `tags` 中加 `案例深化`、`软法-硬法` 等
- 关联页面 `[[policy-xxx]]` 至少新增 1-2 条横向关联（如 `[[policy-minzu-tuanjie-promotion-law]]`）
- 至少 1 个"对五莲县/基层的启示"子项（每个案例后 1 段）

## 4. 常见陷阱

- ⚠️ **不要补法律全文**——破坏 knowledge-base 分工，government-law-wiki 才是法律全文的归宿
- ⚠️ **不要复用旧页面的"⚠️待补充"占位**——必须真正找到真实案例
- ⚠️ **不要把所有"软法-硬法"问题都归为第 6 框架**——只在政策页所列法规**同时存在国家法规和全国性社团自律文件**时使用（如宗教/工商联/光彩/侨联等有"协会"的领域）
- ⚠️ **不要把"软法-硬法"框架加到 5 类问题标注的章节里**——它是**独立的横向框架**，应单独成节
- ⚠️ **不要忘记更新 frontmatter**：`updated` 字段 + `tags` 加 `案例深化`
- ⚠️ **不要忘记更新关联页面**——至少新增 1-2 条 `[[policy-xxx]]` 横向关联

## 6. 中国佛教协会官网抓取技术（2026-06-09 沉淀）

| 模式 | URL / 命令 |
|------|-----------|
| 首页 | `https://chinabuddhism.com.cn/` |
| 文章详情 | `https://chinabuddhism.com.cn/web/details/{id}`（id 为数字，从首页 `onclick` 中提取）|
| 取首页头条链接 | `Array.from(document.querySelectorAll('li')).filter(li => li.innerText.includes('关键词')).map(li => li.outerHTML.match(/details\("?[^"]*"?,\s*(\d+)/)?.[1])` |
| 提取正文 | `document.querySelector('main, .article-content, p')?.innerText.slice(0, 5000)` —— 实际正文在 `<p>` 标签序列中 |
| 编码 | UTF-8（不需要 iconv） |

**与其他官方站点对比**：
- vs gov.cn：内容质量高，**但站点慢**，部分二级页面 404
- vs 中央统战部 zytzb.gov.cn：**佛协站远比 zytzb 稳定**，URL 模式可预测
- vs Bing 搜索：佛协首页的"中国佛教协会新修订规章制度汇编"等头条**比 Bing 准确 10 倍以上**
