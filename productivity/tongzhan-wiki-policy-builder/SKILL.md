# 五莲统战 Wiki 知识库 — 政策页面建设

> 任务定位：**每日 1 个政策文件页面 + 1 条执行案例**。增量建设，不追求一步到位。
> 工作目录：`~/wiki/`
> 提纲：`~/wiki/tongzhan-work-outline.md`
> 产出：`~/wiki/entities/policy-xxx.md`（新增/更新）+ `~/wiki/index.md` 索引 + `~/wiki/log.md` 建设记录

---

## ⚠️ 最重要的陷阱：不要盲信优先级清单

提纲的"优先级排序"是**建设顺序建议**，不是机械顺序。**每个 cron run 第一步**就是列出 `~/wiki/entities/` 现有文件，找出真正仍然"待建"的编号。

- 提纲的状态列（"待建设" / "✅ 已建设"）**可能滞后于实际进度**——昨天有人建了页面但没更新提纲
- 历史案例：2026-06-04 cron 任务，任务书里优先级清单的 P13/P01/P06/P15/P03 实际都已建成，只剩 P05 和 P17 待建
- **判断逻辑**：以 `ls ~/wiki/entities/policy-*.md` 的实际结果为准，不以提纲为准

### ⚠️ 任务书的"优先级列表"也可能是过期的（2026-06-07 新发现）

cron 任务书里写死的优先级清单（如 "P13 → P01 → P06 → P15 → P03"）来自**任务模板**，每次 cron run 时它不会更新。任务书的"步骤 1"说"按以下优先级顺序"——但**该列表对应的政策可能上个月就已全部建完**。

- **正确做法**：把任务书的优先级列表当作"建议"而非"硬性顺序"
  1. 先执行 `ls ~/wiki/entities/policy-*.md` 检查实际现状
  2. **若任务书优先级列表中的政策全部已建**：不要"按列表硬选"，而是按下方"全建完后的应对"逻辑选页
  3. **若任务书优先级列表中部分已建、部分待建**：从待建项中选 1 个

### ⚠️ "优先级列表滞后"是 2 周以上的稳定现象（2026-06-09 强化）

2026-06-09 再次确认：cron 任务书优先级列表中 P13/P01/P06/P15/P03 全部"已建"，且其中 P01（policy-religion-regulations）是**唯一零案例**的页面。这意味着**任务模板在 2026-05 末定型后即使每天 cron 跑 5 个政策的循环，任务书也不会自动更新到"已全部完成"状态**。

- **工作流已稳定**（可固化决策树）：
  - 优先级列表 5 项全"已建" + 多数有 ≥3 案例 → 选**最浅页**深化
  - 优先级列表 5 项中部分"待建" → 从待建项中选
  - 优先级列表 5 项全"待建" → 按编号从小到大选
- **不再需要每天犹豫"该选哪个"**——决策树已定

### ⚠️ 第四档应对：索引页深化（2026-06-09 新发现，与"全文页深化"区别）

P15 章程类全文页深化见 `references/deepen-shallow-page.md` 第 4 节。但**索引页**（如 P01《宗教事务条例》的 `policy-religion-regulations.md`，其正文指向 `~/government-law-wiki/entities/religious-affairs-regulation.md`）的深化模式**不同**：

- **索引页的"内容稀薄"≠ 全文稀薄**——内容稀薄是因为**不重复建法律全文**（分工给 government-law-wiki）
- **深化方向**不是"补法律条文"，而是：
  1. **补真实执行案例**（索引页最容易"暂无经核实的真实案例"——因为前几次建设的"重点"是法律解读不是案例）
  2. **补案例间的制度逻辑串联**（用 ASCII tree 展示多案例如何共同暴露同一制度漏洞）
  3. **补"软法-硬法中间地带"等横向分析框架**（超越"5 类问题标注"线性列举）
- **典型案例**：2026-06-09 深化 P01
  - 原状：113 行 / 5.9KB / 5 类问题标注 / **0 条真实案例**（唯一零案例的政策页）
  - 深化后：218 行 / 12.6KB / 5 类问题标注 / **3 条 2026 年权威真实案例** + 案例间逻辑串联图 + 3 条核心制度问题总结
  - **关键发现**："软法-硬法"中间地带——宗教团体自律性"软法"（如中国佛教协会五年规划纲要）与国家法规"硬法"（如《宗教事务条例》）衔接真空，导致基层执法出现"够不上处罚、够不上追责"的中间地带
  - **新方法论**：在 5 类问题标注之外，第 6 类框架"软法-硬法衔接"应作为索引页深化的标配章节

### ⚠️ 全建完后的应对——"深化最浅页"是合法选项（2026-06-07 新发现）

P01-P17 全部"✅ 已建"后，**不要谎报"无新政策可建"**。最浅页（行数最少、内容最稀、缺真实案例）就是当天任务目标：

- **判断"最浅"**（按以下加权）：
  - 行数 < 70 → 浅
  - 字节数 < 3KB → 浅
  - 含 "暂无经核实的真实案例" / "⚠️待核实真实案例" 占位 → 极浅
  - 章节数 < 5 → 浅
  - 5 类问题标注少于 3 类 → 浅
- **深化范围**：
  - 抓取该政策官网原文（即使是已建设的"社团章程"类，官网也会有最新版本）
  - 重新标注 5 类执行层面问题
  - 补 1-2 条近 3 个月真实执行案例
  - 更新 `created` / `updated` 字段，更新 `log.md` 标注为"update | 深化"
- **实际案例**：2026-06-07 cron 任务——P15 政策页仅 65 行 2.2KB，优先列表其他项都已建，选择深化 P15（章程 8 章 51 条 + 6 条案例 + 5 类问题），扩至 295 行 8.8KB

### ⚠️ 第五档应对：已印发但解读未发布（2026-06-12 P16 实践沉淀）

> **适用场景**：政策文件**已由主管部委正式印发**（在政府官网政策文件库可检索到），**但配套专家解读、政策释义、答记者问等仍未在政策解读栏目发布**。处于"刚印发窗口期"——政策已生效但官方解读滞后。

**与已有 4 种模式的关键区别**：

| 模式 | 原文可获取 | 解读/释义 | 执法案例 | 典型 |
|------|-----------|-----------|---------|------|
| 正常政策页 | ✅ 公开 | ✅ 已发布 | ✅ 已有 | 多数 P0X |
| 未生效新法/软法 | ✅ 公开（人大网） | ✅ 已发布释义 | ❌ 无（未生效） | P17《促进法》2026-07-01 前 |
| 党内规范性文件（不公开） | ❌ 内部掌握 | ❌ 无 | ✅ 有（讲话反推） | P12《党外代表人士双重管理意见》 |
| 索引页 | ✅ 全文在另一个 wiki | ✅ 解读在 government-law-wiki | ✅ 已有 | P01《宗教事务条例》 |
| **本文：已印发但解读未发布** | ✅ 已发布原文 | ❌ 解读未发布 | ⚠️ 少（窗口期） | **P16《创建命名管理办法》2026-01-08 印发版** |

**双轨标注法**（页面建设核心方法论）：

1. **顶部"政策状态说明"块**：
   ```markdown
   > **政策状态**：本《办法》于 YYYY-MM-DD 印发，原文可在 [官网URL] 获取。
   > **解读状态**：截至 YYYY-MM-DD（今日）抓取，**专家解读/政策释义/答记者问尚未在政策解读栏目发布**。
   > **执行状态**：**实施细则/配套规则/具体操作指南尚未发布**。
   > **本文处理策略**：以最新已解读的同名前一版（如有）作为分析锚点。
   ```

2. **条款摘录分块标注**：来自前版解读的明确条款 + 来自印发原文但无解读的条款 — **分开标注**

3. **案例章节"分档"标注**：A 类（前版解读案例）+ B 类（同期权威报道）+ C 类（待补占位）

**3 档案例替代来源**（按可靠性排序）：

1. **第 1 档：前一版同名称办法的解读**（最可靠）— 在政策解读栏目按"按时间倒序"查找
2. **第 2 档：同期主管领导公开讲话/署名文章**— 直接访问 neac.gov.cn 首页"民委要闻"
3. **第 3 档：同期相关上位法/平行法的解读**— 间接定位本《办法》在上位法框架下的位置

**5 类"刚印发窗口期"信号识别**（解读延迟本身是制度信号）：
- 印发后无答记者问
- 政策解读栏目仍为旧文
- 学术论坛/署名文章未跟进
- 配套实施细则未起草迹象
- 地方"先行先试"案例缺失

**完整处理手册**：见 `references/issued-but-uninterpreted.md`

**抓取技术专用手册**：neac.gov.cn 是民族工作领域的"金矿"——URL 模式固定、首页 listing 是 HTML 静态渲染、policy interpretation 分页 `index_2.shtml` 真实可用。**见 `references/neac-url-patterns.md`**。

**真实案例**：P16《创建命名管理办法》2026-01-08 印发版——解读 5 个月仍未发布；学术焦点已转移到上位法《促进法》（2026-05-23 论坛、2026-04-29 关凯文章主题都是《促进法》不是《办法》）；3 档案例替代法有效——以 2024-03 修订版（已配套 2024-03 解读）作为分析锚点。

### ⚠️ 党内规范性文件原文不公开的处理方法（2026-06-11 P12 实践沉淀）

> **适用场景**：中央组织部、中央统战部、中办、国办等联合印发的**党内规范性文件**——发布层级低于党内法规（如 P13《中国共产党统一战线工作条例》是党内法规），原文不在中央统战部官网公开，仅"内部掌握、适当公开"。

**与已有"未生效新法/软法"模式的区别**：
- **未生效新法**（P17 模式）：法律已通过即将生效，**无执法案例**但有"准备实施阶段信号"
- **党内规范性文件**（P12 模式）：已生效多年，**无原文公开**但有**中央领导公开讲话信号**

**P12《意见》原文不公开但能找到的事实证据**（2026-06-11 实践）：
1. **2026-05-20 李干杰在党外代表人士队伍建设研讨会的讲话**——讲话本身提到"近期中共中央印发有关文件"，**反向证实**有文件存在
2. **2026-04-22 中央统战部党外人士形势政策报告会**——证明"双重管理"在中央层面仍在运作
3. **P13《统一战线工作条例》第三章**——是 P12《意见》的母法依据

**处理策略（6 步）**：
1. **承认原文不可得**——在页面顶部明示"原文未在政府官网公开全文，属'内部掌握、适当公开'层级"
2. **采用"2026 公开讲话反推"路径**——从中央领导最新讲话中提取对原文条款的引用、评价、问题承认
3. **标注"基于领域知识 + 公开讲话反推"**——条款摘录前加 ⚠️ 声明
4. **优先收录中央领导讲话信号作为案例**——讲话中的"针对性实效性"等用语**本身就是制度漏洞证据**
5. **明确"跟踪"待办**——把"跟踪新文件公开"列入下步研究
6. **配套 raw 摘要单独说明"原文获取难度评估"**——含建议获取路径（共产党员网党内法规库、中央组织部官网等）

**真实案例**：P12《关于进一步规范党外代表人士双重管理工作的意见》——页面重建后 282 行 / 19KB / 5 类问题全覆盖 / 2 条 2026 年中央讲话案例

## 工作流（5 步）

### 步骤 1：选政策

```
1. ls ~/wiki/entities/ | grep ^policy | sort  # 已有
2. 对照提纲"政策文件库"表（第二节 2.1），找状态为"待建设"且不在已有列表中的编号
3. 选 1 个政策建设
   优先：P 编号最小（避免长期跳过） / 与近 3 天主题相关（避免跨领域跳跃）
```

**⚠️ "已建"≠"已建全"——区分"全文页"与"索引页"**（2026-06-05 重要经验）：

有些政策虽标记"✅ 已建设"但**只是索引页**，不是完整的 policy-xxx.md：
- **P01《宗教事务条例》**：`policy-religion-regulations.md` 是索引页，法律全文在 `~/government-law-wiki/entities/religious-affairs-regulation.md`
- 提纲"✅"标记 + 描述"已关联 government-law-wiki"是**已建**信号，不是待建信号

**判断方法**：
```bash
# 看文件头 10 行确认是索引页还是全文页
head -15 ~/wiki/entities/policy-{slug}.md
# 含 "本页面为索引页" / "实际法律条文和法律责任分析见 government-law-wiki" → 索引页
```

**何时选择"补全索引页"vs"建新政策"**：
- 若该政策在统战执行层面有重大变化（如新配套法规）→ 补全索引页
- 若该政策已稳定 → 选下一个"待建设"政策
- **本知识库的分工**：政府法律知识库存条文，本知识库只做执行层面分析

### 步骤 2：抓取法律原文

### 步骤 3：搜索近期执行案例（近 3 个月）

**首选策略**——**直接访问权威网站首页的"最新发布"/"头条"**：
- 国台办首页 → "头条" 列表（2026-04-12 "十项措施" 就是这么找到的）
- 商务部台港澳司 → 政策法规栏目
- 国家宗教事务局 → 新闻动态
- 中央统战部 → 统战动态

**次选**——Bing 搜索：
```
browser_navigate("https://cn.bing.com/search?q={政策关键词}+{问题关键词}+site:gov.cn")
```

**⚠️ 搜索引擎 CAPTCHA 警告**：
- Bing 在中国 IP 下频繁弹"最后一步"人机验证
- 搜狗 (`sogou.com`) 反爬更严，直接 `页面没有找到`
- 备选：直接访问新华社/人民日报/观察者网官网的关键词搜索
- **最稳妥的路径：直接打开相关政府机构首页**（见首选策略）

**⚠️ Bing 搜索结果可能"被本地化过滤"**（2026-06-05 新发现）：
- 多次不同关键词搜索均返回**相同的 10 条 generic 结果**（百度百科、各类百科）
- 页面底部出现"为回应符合本地法律要求的通知，部分搜索结果未予显示"
- 表面上 `b_results` 元素存在但内容固定，无法获取新结果
- **应对**：跳过搜索引擎，**直接走首选策略**——访问国家民委 neac.gov.cn / 中央党校 ccps.gov.cn / 新华网 news.cn 的首页或对应栏目，手动浏览"时政要闻"列表
- **新法/未生效法的案例替代方案**：若 Bing 实在返回不了新结果，可改用"近期官方释义文章 + 学术论坛动态 + 主管机关部署会议"作为"未生效期间的制度问题信号"（详见下方"未生效新法处理方法"小节）

**⚠️ Bing 搜索结果可能被"语义污染"返回毫不相关的结果（2026-06-08 新发现）**：
- 搜"同等待遇 台民 2026 政策"返回 Spotify、YouTube、Rolls-Royce Spectre、Pizza 站点的链接
- 搜"台胞职业资格壁垒 2026 制度"同样返回 cargurus、pizzahut 等英文站点
- 推测是 Bing 中国版搜索服务降级或返回默认"泛匹配"结果
- **应对**：**遇到 Bing 返回 >50% 不相关结果 → 立即放弃 Bing**，切到首选策略（直接访问权威站点首页），不要继续尝试不同关键词
- **关键判定**：用 `grep -oE 'href="https?://[^"]*"' | sort -u` 后，看 `gov.cn` / `xinhuanet.com` / `rmzxw.com.cn` 等权威域名是否 <30% —— 是则放弃

**⚠️ 中文词义"消歧失败"导致 Bing 返回完全不相关结果（2026-06-09 强化）**：
- 搜"统一战线 基层 执行 问题 2026" → 返回**统一企业**（Uni-President，台资食品公司）、**统一（汉语词语）**百度百科
- 搜"李干杰 甘肃四川 宗教事务治理法治化" → 返回**李姓族谱**、**李姓起源**等百度百科条目
- 搜"宗教事务条例 实施 问题 2026" → 返回**宗教（社会特殊意识形态）百度百科**、**世界十大宗教**等通用内容
- **根本原因**：Bing 中国版对**多字专有名词**的语义解析退化为**取其中高频独立名词**做匹配（统一/李/宗教），**忽略上下文语境**
- **应对**（优先级排序）：
  1. **加引号锁定短语**（如 `"统一战线工作条例" 基层 执行`）——但效果有限
  2. **加 `site:` 限定**（如 `site:gov.cn`）——Bing CN 对 site: 的支持也**不稳定**，常被忽略
  3. **加年份限定**（如 `2026`）——小幅改善
  4. **若上述 3 招都失败 → 立刻放弃 Bing**，按下方"直接访问权威站点首页"路径
- **直接访问权威站点首页"绕过 Bing 失败"的标准动作**：
  ```bash
  curl -sL -A "Mozilla/5.0" "https://www.chinabuddhism.com.cn/" | grep -oE 'onclick="details\([^)]+\)"'
  ```
  比 Bing 搜索快 10 倍、准 10 倍（特别是宗教、统战领域——这些官方站点首页质量极高）

**⚠️ 直接访问权威站点首页是最稳的路径（2026-06-08 实践确认）**：
- `curl https://www.gwytb.gov.cn/` → 一次返回 20+ 条 `t2026{MM}_{id}.htm` URL，5-6 月 2026 链接全部 200 OK
- 比 Bing 搜索快 10 倍、准 10 倍
- **重点看首页的"头条"列**（topone/）、"地方动态"列（local/）、"部门涉台"列（bmst/）
- **批量验证流程**：
  ```bash
  curl -sL -A "Mozilla/5.0" "https://www.gwytb.gov.cn/" | iconv -f gb2312 -t utf-8//IGNORE | grep -oE 'href="[^"]*t20[0-9]+_[0-9]+\.htm"'
  ```
- 然后对每个 URL 跑 `curl -sL` + `iconv -f gb2312 -t utf-8` 提取标题/正文
- **gb2312 编码陷阱**：很多中国政府站用 gb2312/gbk，`curl` 出来是乱码，必须 `iconv -f gb2312 -t utf-8//IGNORE`（`//IGNORE` 跳过无法转换的字节）

**⚠️ Bing 搜索结果 URL 大量 404（2026-06-06 新发现）**：
- Bing 列出的搜索结果看起来 URL 完整（如 `qstheory.cn/dukan/qs/2022-07/15/c_xxx.htm`、`epaper.tibet3.com/qhrb/html/2022-06/21/content_xxx.htm`、`yndaily.yunnan.cn/content/202206/21/content_xxxx.html`）
- **实际全部返回 404**——Bing 索引的链接已被源站清理
- **应对**：不要直接相信 Bing snippet 里的 URL；**优先打开 Bing 列出的 gov.cn / xinhuanet.com 等核心域名的链接**（这些通常稳定）；其他次级域链接先 curl HEAD 验证再写入 sources

**⚠️ 中国政协网搜索 URL 模式不稳定（2026-06-06 新发现）**：
- `cppcc.gov.cn/zxww/search.html?keyword=...&page=N` 和 `rmzxw.com.cn/search.html?keyword=...` 均返回空页或 404
- 中国政协网的站内搜索只能通过首页搜索框交互触发，URL 不可直接构造
- **应对**：使用首页搜索框 + 浏览器交互；或直接访问"权威发布"/"协商"等固定栏目

### ⚠️ 中央统战部"统战时讯"列表的分页参数（2026-06-11 验证）

- 列表 URL：`https://www.zytzb.gov.cn/zytzb/sy/tzyw/index.shtml`
- 默认仅显示最近 5-7 条
- **分页参数：`?pageNo=N`**（N 从 2 开始），可访问更早的历史文章

- **典型发现**：在 `pageNo=2` 中可挖出 2026-04-22 中央统战部党外人士形势政策报告会（对应 P12 党外代表人士双重管理）

### ⚠️ tirith 扫描器对 heredoc 中中文 URL 的拦截（2026-06-11 新发现）

- `cat >> file.md <<EOF ... https://...中文... EOF` **会被 tirith 拦截**（pattern: `tirith:non_ascii_path`）
- 即使 URL 编码正确，heredoc 内部的非 ASCII 字符也会触发误判
- **应对**：log.md 追加改用 `patch` 工具的 `old_string`/`new_string`，把"现有最后一行"作为锚点 patch 进去
- **不要**：为绕过检测手动 URL 编码——这是隐藏问题而非修复
- **可继续用 heredoc 的场景**：纯英文内容、无中文 URL、不涉及本地文件写入

### ⚠️ index.md"总页数"基准约定（2026-06-11 沉淀）

- "总页数"仅计 `~/wiki/entities/`、`~/wiki/concepts/`、`~/wiki/comparisons/`、`~/wiki/queries/`、`~/wiki/log.md` 等**主页面**
- **不计** `~/wiki/raw/`（原始资料）、`~/wiki/articles/`、`~/wiki/papers/`、`~/wiki/transcripts/`、`~/wiki/assets/` 等支撑目录
- **仅深化现有页（不新建 entity）→ 总页数不变**（即使新增了 raw 摘要）
- **新建 entity 页 → 总页数 +1**
- **新建 comparison 页 → 总页数 +1**
- 顶部日期从 `最后更新: YYYY-MM-DD` 反映**任意**索引变化（深化也要更新）

### ⚠️ 长期置顶公告的"信号价值"（2026-06-07 新发现）

某些政府/社团官网会把**"紧急声明""严正声明""特别声明"** 等通告**长期置顶在首页顶部**——例如 cspgp.org.cn 首页置顶的《关于中国光彩事业促进会未投资任何公司、企业、未授权任何公司、企业使用"光彩事业"文字和图形商标的公告》（2023-03-03 发布，2026-06-07 仍在置顶）。

- **置顶 3 年 = 该问题长期存在且无解**——这是**研究"制度漏洞"的金矿**
- 在案例分析时应**同时记录"发布日"和"截至查询日仍在置顶"两个时间点**
- 反映的常见制度问题：
  - 品牌保护/知识产权执法跨部门边界模糊
  - 全国性社团对地方冒用行为的预防监测机制缺位
  - 公告只说"将采取法律措施"但**未公开任何已处罚案例**——震慑效果存疑
- **写作模板**：用"声明发布日 + 长期置顶 + 配套监测/执法信息缺失"三要素构造案例
- **同模式其他可挖站点**：
  - cspgp.org.cn 首页顶部
  - 各省/市民政厅"严正声明"栏目
  - 工商联系统"假冒企业名单"栏目（如有）

### ⚠️ "社团 + 基金会"双实体结构的页面处理（2026-06-07 新发现）

很多统战领域组织是**"两块牌子、两套治理"**：
- **社团**（如中国光彩事业促进会、中华职业教育社、中国侨联）：负责会员管理、活动组织、政治引领
- **基金会**（如中国光彩事业基金会）：负责募捐、资助项目、资金管理
- **两套章程**：社团章程规范会员和活动，基金会章程规范资金和项目

**易混淆点**：
- 公众、捐赠人难以区分两块牌子
- 章程中"促进会"和"基金会"业务范围常存在重叠（如"公益慈善活动组织"）
- 公开披露只在基金会层面做（如 cspgp.org.cn 季度披露是**基金会**的，不是**促进会**的）

**写政策页时的处理建议**：
- 页面顶部明确写"本文件是规范**促进会**的章程，**基金会**另设《基金会章程》与专项基金管理办法"
- 章程/业务范围分析时**只针对促进会**，避免与基金会章节混淆
- 若涉及资金管理/募捐议题，应在页面中标注"该议题由基金会章程另行规定"
- 关联页面：可考虑为基金会单独建 `policy-guangcai-foundation.md` 配套页面（如果未来需要深挖）

**同模式其他可能涉及的领域**：
- 工商联（社团） vs 中华工商时报基金会 / 各地工商联基金会
- 中国侨联 vs 中国华侨公益基金会
- 中华职教社 vs 温暖工程公益基金

**案例应包含字段**：
- 标题、发布日期、来源 URL
- 反映的制度问题（具体到条款/机制）

### 步骤 4：写入 policy-xxx.md 页面

#### 4.0 未生效新法 / 软法 的特殊处理（2026-06-05 P17 实践）

> **适用场景**：法律刚通过、尚未生效；或法律性质是"促进法"类软法（无明确罚则）

**与传统政策页面的差异**：
- **没有"真实执法案例"**——因为还没人或部门被追责
- **"执行案例"需重新定义**——改为"准备实施过程中的制度信号"
- **"问题标注"重点**转向：
  - 立法技术本身（条款语言、章节结构）
  - 配套实施细则是否同步
  - 基层学习/培训准备是否充分
  - 学术界/实务部门对法律性质的争论

**案例替代来源**（按可靠性排序）：
1. **主管机关署名文章**（如 2026-05-13 国家民委"为推进中华民族共同体建设夯实法治根基"）——文中"从行政推动为主向法治保障为主转变"等表述**本身就是制度漏洞证据**
2. **党校/学习时报释义文章**（如 2026-04-14 中央党校 ccps.gov.cn）
3. **实施前研究论坛**（如 2026-05-23 第五届铸牢中华民族共同体意识研究论坛）——焦点议题反映"原则→操作"转换困难
4. **部署会议**（如 2026-06 初全国民委主任会议，距生效日不足1个月）——反映准备仓促

**⚠️ 不可伪造"执法案例"**：未生效法不存在"违反案例"，硬凑将污染知识库。**显式标注**"未生效期间信号"或"准备阶段制度问题"以区别于已生效法的真实执法案例。

**软法性质自评要点**：
- 翻遍全文，"促进""鼓励""深入"等倡导性条款占比 > 50%？→ 软法倾向
- "应当""必须"等义务性条款少？
- 法律责任章节是否仅原则性表述（"依法追究责任"）而无具体罚则？
- 监督检查是否依赖党政考核而非独立监督机构？

#### 4.1 文件命名
- 格式：`policy-{slug}.md`
- slug 规则：拼音/英文短名，如 `policy-taiwan-investment`、`policy-31-measures`
- **不**用编号开头（如 `policy-05`），因为编号会变

#### 4.3 章节结构（8-9 章节，按需裁剪）

1. **抬头**：正式名、首次通过/修正/生效版本、配套法规
2. **出台背景与立法定位**：对台/宗教/工商联体系中的位置
3. **核心规定（条款摘要）**：表格化呈现
4. **执行层面问题标注 ⚠️**（最核心章节，必须有）
5. **配套法规体系**：子法规、地方实施条例
6. **典型案例/新闻**：步骤 3 找到的 1-2 条
7. **相关政策链接**：`[[policy-xxx]]` Obsidian 双向链接
8. **信息稿选题角度提示**：7 个左右（可选）
9. **知识库建设记录**：建设日期、内容简述

#### 4.4 5 类"执行层面问题"标注框架（核心方法论）

| 类别 | 关注点 | 典型问句 |
|------|--------|----------|
| ① 模糊地带 | 立法语言本身模糊 | 哪些条款用"原则上""视情况""依法""国家需要"等抽象词？基层会怎么理解？ |
| ② 执行空白 | 有要求无细则 | 条款要求"建立 X 机制""享受 Y 待遇"——但具体标准/程序/认证在哪里？ |
| ③ 多部门协调 | 部门边界不清 | 涉及哪几个部门？哪类边界最常推诿？是否有部际协调机制？ |
| ④ 监督追责 | 无具体罚则 | 违反条款如何处理？由谁监督？有无独立的监督机构？ |
| ⑤ 历史遗留 | 立法范畴滞后 | 立法后是否有新法/新情况让母法脱节？（如《外商投资法》对接问题） |

**呈现方式**：
- 表格化（条款 → 模糊点/空白点/后果）优于纯文字
- 标注 ⚠️ 符号突出
- 数量建议每类 2-5 条，**真实**而非凑数

### 步骤 5：更新索引与日志

**index.md 更新**：
- 找到"统一战线工作 → Entities（政策文件，已建）"章节
- 在最后一条已建条目后追加新条目（一句话摘要 + 标注几类问题）
- 从"Entities（政策文件，待建）"列表中移除已建编号

**⚠️ index.md 多 agent 并发冲突（2026-06-05 新发现）**：
- patch 工具可能返回警告"此文件被 sibling subagent 修改过，但本 agent 从未读取"
- 即使按"已读"流程操作，仍可能因**其他 cron job 同步修改**导致章节重复或顺序错乱
- **强制流程**：
  1. 写 policy-xxx.md **之前**完整 read_file 一次 index.md
  2. patch index.md 之后，**必须再 read_file 一次**确认
  3. 若发现重复章节（如两个"### Concepts"），立即 patch 删除多余项
  4. 同步更新顶部"最后更新"日期和"总页数"
- **反模式**：用多条独立 patch 增量插入而不读全文，极易产生重复或漏改

**log.md 更新**（追加，不覆盖）：
```markdown
## [YYYY-MM-DD] create | policy-xxx.md
- 新建 PXX 政策页面：《政策名》（通过/修正/生效版本）
- 来源：xxx
- 标注 N 类执行层面问题：
  1. ...
  2. ...
- 收录 M 条近期执行案例：
  1. YYYY-MM-DD ...（来源）
  2. ...
- 辅助文件：raw/xxx.md
- 同时更新 index.md：将 PXX 移入已建列表
```
